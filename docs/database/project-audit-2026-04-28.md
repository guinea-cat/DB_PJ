## 2. 项目整体架构

当前项目不是“纯 SQL 脚本作业”，而是一个完整的前后端课程项目：

- 后端：FastAPI
- 数据库访问：SQLAlchemy ORM
- 迁移：Alembic
- 数据库：SQLite 本地演示 + MySQL 实库验证
- 前端：Vue 3 + Vite

整体调用链如下：

1. 前端调用 REST API。
2. 路由层负责鉴权、参数接收、角色隔离。
3. 服务层负责核心业务规则。
4. SQLAlchemy 把 Python 操作翻译成 SQL。
5. 数据库负责外键、唯一约束、检查约束和事务锁。

这个结构对“工程实现”是加分项，但也意味着答辩时必须解释清楚：

- 数据库设计本身是什么；
- Python 代码只是数据库逻辑的承载方式，不是逃避数据库设计。

这些扩展不是违背课程要求，而是“在核心设计之上的合理增强”。答辩时应明确说清：**核心数据库设计仍以 11 张主表为主，扩展表用于权限、排班、候补和审计。**

### 5.1 符合项

1. 满足 3NF 主体思路。
   - 交易表没有冗余保存城市名、机场名、飞机型号等可传递推导字段。

2. 正确拆解了“航班-机场”多对多。
   - 用 `RouteSegment` 表示经停链路。

3. 正确拆解了“航班-库存”问题。
   - 用 `ScheduleInventory` 按航段维护余票。

4. 支持每周班期。
   - 用 `FlightTemplate + FlightTemplateWeekday` 实现，比简单字段更规范。

5. 存在完整的 B 端 / C 端权限边界。

6. 已实现事务型购票和退票流程。

### 5.2 偏差项或需解释项

1. 实际项目比 E-R 图扩展更多表。
   - 这是增强，不是错误，但答辩时要说明“核心模型仍未改变”。

2. 当前项目主要通过 Python ORM 实现，不是手写原生 SQL 页面逻辑。
   - 这在工程上成立，但在“课程要求强调 SQL 编写”这一点上，需要补充说明和 SQL 文档支撑。

3. 候补当前是“释放通知”，不是“自动出票”。
   - 符合当前项目文档，但弱于设计思路里提到的更强自动化方案。

4. 支付信息未单独建模。
   - 课程要求关注支付信息安全，但当前系统采用“下单即已支付”的简化策略，规避了真实支付字段存储。

## 6. 并发售票、特价票、安全隐私专项结论

### 6.1 并发售票与锁机制

结论：**已实现，且经实测有效。**

实现方式：

- `purchase_ticket()` 中对目标航段库存执行锁定读取
- 再统一判断最小余票
- 库存足够时才扣减并写入订单

实测结果：

- MySQL 实际接口并发验证中，一张余票下两个并发购票请求只成功一单，另一单返回 `409`
- 候补释放场景在 MySQL 接口实测中也符合预期

### 6.2 特价票与差异化售票

结论：**已基本实现，但“特价策略维度”仍偏简单。**

当前已有：

- 航线基础价格：`RoutePricing.base_price`
- 航班折扣：`FlightSchedule.flight_discount`
- 用户等级折扣：`UserType.discount_rate`

公式：

- `最终票价 = 航线基础价 × 航班折扣 × 用户类型折扣`

不足：

- 没有单独的促销规则表
- 没有时间窗特价、余票阶梯定价、节假日定价等更复杂销售策略

### 6.3 数据安全与隐私保护

结论：**有一定保护，但还不够高标准。**

已完成：

- 密码使用 `bcrypt` 哈希
- JWT 鉴权
- 管理员与普通用户角色隔离
- 管理员订单接口已改为身份证脱敏输出
- 系统不保存真实银行卡/支付流水

仍不足：

- `Passenger.id_card` 在数据库中明文存储
- 乘客姓名也为明文
- JWT 默认密钥仍是开发占位值，生产必须替换
- 没有字段级加密、脱敏视图、细粒度审计查询权限

## 9. 对“Python 是否能替代 SQL”的结论

结论分两层：

1. **工程实现层面：可以。**
   - SQLAlchemy 本质上仍在生成并执行 SQL。
   - 事务、锁、外键、约束、索引这些数据库能力并没有消失。

2. **课程规范层面：不能完全等价替代“展示 SQL 能力”。**
   - 如果老师明确要求“使用 SQL 语句开发”，那只交 Python ORM 代码会显得不够直接。
   - 最稳妥做法是保留当前 Python 实现，同时补齐：
     - `flight_ticketing_db.sql`
     - 关键业务 SQL 示例
     - 事务/锁机制的 SQL 说明

因此，当前项目**在工程上成立，在课程表达上需要补充 SQL 说明材料才更稳妥**。
